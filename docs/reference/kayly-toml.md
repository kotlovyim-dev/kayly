# `kayly.toml` reference

`kayly.toml` sits at the root of the app and describes its shape: how to build it, the command that runs before each release, its services and the env keys they need. Values of secrets never go in this file; they live in Kayly (`kayly env set`). Unknown keys are an error, reported with file, line and column, so a typo never passes silently.

```toml
[build]
dockerfile = "Dockerfile"            # omit to build with Railpack
target = "app"

[release]
command = "node src/db/migrate.ts"   # runs once per release, before any service starts

[services.app]
command = "node src/server.ts"
port = 3000
health = "/api/ready"
volumes = ["uploads:/data/uploads"]
memory = "512m"
cpus = 1.5

[services.worker]
command = "node src/worker.ts"
volumes = ["uploads:/data/uploads"]

[env]
SESSION_SECRET = { generate = "base64:32" }
DATABASE_URL   = { template = "postgres://app:${DB_PASSWORD}@${postgres.host}:5432/app" }
DB_PASSWORD    = { generate = "hex:32", to = [] }
ADMIN_URL      = { template = "${postgres.url}", to = ["release"] }
PUBLIC_URL     = { template = "${app.url}" }
SMTP_URL       = {}
SENTRY_DSN     = { required = false }
```

## `[build]`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `dockerfile` | path inside the app | none | Build with this Dockerfile (`docker buildx build`). Without it, Kayly builds with [Railpack](https://railpack.com), which detects Node, Python, Go, Ruby, PHP, Java, static sites and more. |
| `target` | string | none | The Dockerfile stage to build. Needs `dockerfile`. |

## `[release]`

| Key | Type | Meaning |
|---|---|---|
| `command` | command | Runs once in a one-off container from the new image, with the release env, before any service of the release starts. Exit 0 continues the deploy; anything else fails the release and leaves the live one serving. Use it for database migrations. Postgres is backed up just before it runs. |

## `[services.<name>]`

A service is one long-running process. Its name is 1 to 31 characters of `a-z`, `0-9` and `-`, starting with a letter; `release`, `postgres` and `redis` are reserved.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `command` | command | the image's | Replaces the image's entrypoint and command. Runs without a shell: words are split as a shell would, but there are no pipes, `&&` or `$VAR`. Use `sh -c '…'` for those. |
| `port` | 1–65535 | none | The port the service listens on. A service with a port gets HTTPS at `https://<service>.<project>.<base domain>` and can take custom domains. Without one it is a worker. |
| `health` | path starting with `/` | TCP check | Checked with HTTP GET before traffic moves; a 2xx passes. Needs `port`. Without it, a TCP connect to the port is the check; a service without a port passes when it has run 10 s without a restart. |
| `volumes` | `["name:/abs/path"]` | none | Project volumes (Docker volume `kayly_<project>_<name>`). They outlive releases and are backed up daily. Two services may mount the same volume. |
| `overlap` | bool | `true` | `false` stops the old container before the new one starts: a short gap, for singletons. |
| `read_only` | bool | `false` | Read-only root filesystem with a tmpfs on `/tmp`. |
| `ports` | `["7882/udp", "3478/tcp"]` | none | Published on the host at the same numbers, for traffic HTTP cannot carry. 80 and 443 belong to the proxy. A service with `ports` never overlaps. |
| `memory` | `"512m"`, `"1.5g"` | unlimited | RAM cap (k, m or g, powers of 1024; at least `6m`). Swap is off. |
| `cpus` | number | unlimited | CPU cap in cores, e.g. `0.5` or `2`. |

Every service runs with restart `unless-stopped`, `no-new-privileges`, all capabilities dropped, log rotation of 5 × 10 MB and a 30 s stop grace period.

### `[services.<name>.telegram]`

Makes the service a Telegram bot; see [Telegram bots and Mini Apps](../bots.md).

| Key | Type | Meaning |
|---|---|---|
| `token` | env key | The `[env]` key holding the bot token. It must reach this service. Kayly calls `getMe` with it before anything live changes; a bad token fails the release. |
| `mode` | `"webhook"` or `"polling"` | Webhook needs `port`. Polling implies `overlap = false`. |
| `path` | path | Webhook only: where Telegram posts updates, e.g. `/telegram`. |
| `menu_button` | `{ text, url }` | Optional: a menu button that opens a Mini App. `url` is `https://…` or uses `${<service>.url}`. |

A webhook bot receives `TELEGRAM_WEBHOOK_SECRET`, generated by Kayly; declaring that key yourself is an error.

## `[env]`

Each line declares one variable. Only declared keys are delivered: a value stored in Kayly for a key that is no longer here is ignored and reported, so deleting a line can never leak a secret to every service. Keys match `[A-Z_][A-Z0-9_]*`.

| Form | Meaning |
|---|---|
| `KEY = {}` | Set by you: `kayly env set KEY=…`. Required: a deploy without it fails in seconds, before the build. |
| `KEY = { required = false }` | Set by you, optional. |
| `KEY = { generate = "hex:32" }` | Random, created on the first deploy (`hex:N` or `base64:N`, N bytes) and kept until you set another value. |
| `KEY = { template = "…" }` | Resolved at release time. See below. |
| `to = ["app", "release"]` | Delivered only to these services and/or the release step. Without `to`, every service and the release step get it. `to = []` delivers it nowhere: it only feeds templates. |

`template` may use:

- `${KEY}`: another variable of this file;
- `${<service>.url}`: the service's public URL, the first custom domain if there is one, else its sslip.io address;
- `${postgres.host|port|user|password|db|url}` with the Postgres add-on attached; `${postgres.url}` is the superuser URL, so scope it;
- `${redis.host|port|password|url}` with the Redis add-on attached.

Add-ons are attached in Kayly, not here (`kayly addons add postgres`). They inject `DATABASE_URL` or `REDIS_URL` into every target unless this file declares that key itself, which takes it over.

## Compatibility

From v1.0 this format follows semantic versioning: a file valid for 1.x stays valid and means the same in every later 1.x. New keys may be added; nothing is removed or changes meaning before 2.0. See [compatibility](../compatibility.md).
